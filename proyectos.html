Sistema de Gestión / Restaurante01

Como Arroz

Sistema de gestión y pedidos para restaurante.

“De pedidos por WhatsApp a una operación digital centralizada.”

// PROBLEMA

El restaurante tenía un sistema de pedidos basado principalmente en WhatsApp, lo que dificultaba organizar el proceso y trabajar de forma eficiente.

// SOLUCIÓN: CLIENTE → CAJA → COCINA

Plataforma web que centraliza tres áreas principales: el cliente realiza el pedido, en caja se verifica el pago (transferencia o efectivo) y una vez confirmado pasa a cocina para coordinar la preparación, avance y despacho.

Funcionalidades desarrolladas
  • Catálogo y gestión de productos
  • Categorías
  • Gestión de imágenes
  • Panel administrativo
  • Sistema de pedidos y estados
  • Gestión de pagos
  • Flujo de preparación en cocina
  • Gestión del proceso hasta el envío

// MI PAPEL:Conceptualización, Arquitectura, Diseño, Desarrollo, Despliegue

  • Python
  • Django
  • PostgreSQL
  • JavaScript
  • HTML
  • CSS
  • Bootstrap
  • Cloudinary
  • Render

Prospector C&D

Herramienta de prospección comercial.

“Convertir búsquedas dispersas de empresas en información estructurada para facilitar la prospección comercial.”

// PROBLEMA

Una persona dedicada a servicios de cargue y descargue necesitaba encontrar empresas potencialmente relacionadas con estos servicios dentro de determinadas zonas.

// SOLUCIÓN

Herramienta para realizar búsquedas de empresas según zona y criterios determinados mediante Brave Search, organizar los resultados y exportarlos.

Capacidades del sistema
  • Búsqueda por zona.
  • Búsqueda según criterios.
  • Visualización de resultados.
  • Organización de empresas.
  • Almacenamiento de resultados.
  • Exportación a Excel.

Criterio técnico

Problema → Solución → Desarrollo

Enfoque centrado en comprender las necesidades operativas reales antes de escribir código. Cada línea implementada responde a un requerimiento funcional claro.

01 // PROBLEMA

Diagnóstico operativo

Comprensión exhaustiva del dolor del usuario o negocio: cuellos de botella en pedidos, datos no estructurados o flujos manuales propensos a fallas.

02 // SOLUCIÓN

Diseño de arquitectura

Definición del modelo relacional, selección pragmática de tecnologías y delimitación de módulos funcionales (cliente, caja, cocina, persistencia).

03 // DESARROLLO

Desarrollo y entrega

Código limpio, estructuración robusta de backend y frontend responsive, listos para operar con estabilidad y documentación clara.
